# Cloud transport result

## Scope

This task changed only the host plugin transport and its focused tests. No
firmware, protocol messages, approval handling, shared documentation, or
dependency configuration was changed. Context7 documentation tooling was not
available in this environment, so the implementation was based on the Python
standard-library APIs, the installed WebSocket API, and loopback tests.

## Result

- TCP input now uses a bounded newline framer with the device's 4,095-byte
  payload limit. An oversized line is discarded through its newline and a
  later valid line on the same connection is still accepted.
- Token-protected TCP and WebSocket clients must authenticate within a bounded
  interval. Oversized or invalid TCP authentication is rejected without
  interpreting a valid-looking suffix.
- WebSocket message size is capped at 4,095 bytes by the server. Malformed
  in-limit messages remain isolated and a later valid message is accepted.
- Slow outbound clients retain their existing private bounded queues. Failed
  writers are removed without blocking healthy clients.
- `SerialLink.stop()` now shuts down every listener started by the instance,
  disconnects registered clients, stops their sender workers, and drops the
  serial handle. This makes listener and connection lifecycle explicit while
  preserving the public start methods and legacy no-token clients.

## Verification

Focused loopback tests cover TCP authentication, exact framing limits,
oversize recovery, malformed input recovery, idle unauthenticated clients,
reconnects, slow-client isolation, listener shutdown, and malformed WebSocket
recovery. All 18 focused tests passed in an isolated `uv` environment with a
current WebSocket package. The base environment also passed its 14 available
focused tests and skipped four WebSocket tests because its installed package
does not expose the synchronous API.

The full host run completed with 114 tests passing, 6 skipped, and 20,807
subtests passing. Its single failure was the pre-existing native storage runner
requiring ArduinoJson generated by a prior V1 PlatformIO build; this transport
task does not own firmware or shared test infrastructure. No physical hardware
claims were made and the gateway plugin was not deployed.
